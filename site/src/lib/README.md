# `src/lib`: course data, deadlines and saved progress

The data layer every page uses. Pages import from `@src/lib` (plain functions) and `@src/lib/react` (hooks) and nothing else.

- **Pure.** No DOM or storage access at import. Every time-dependent function takes `now` (a `Date` or epoch ms; omit it for the current time) so tests can pin the clock.
- **The old site's rules, unchanged.** Deadlines come only from the vendored `targets.mjs` + `schedule.mjs` (Toronto time, the end-of-day rule, precision levels, the 2-hour grace, the overall winner). Wording comes from the old pages.
- **The old site's saved progress, unchanged.** The same `localStorage` keys and byte-identical values (table below), so progress saved on the old site appears here and vice versa. Ticks and completion records stay separate.
- **Never crashes on storage.** Empty, missing, blocked (throws) or full storage reads as "nothing saved"; writes report `saved: false` and are kept in memory for the page view.
- **Server rendering.** Time and storage are client facts. Hooks return `null` / empty values until mounted, so the exported HTML never bakes in a build-time "now" or anyone's progress. Static data (`COURSES`, `assessments`, `courseInfo`, `sections`) is safe at build time.

Every write re-reads storage, applies one change and writes the whole cleaned record: exactly what the old page wrote for that action after loading. Readers never write. `mth14x-view-v1`, `tmu-guide-theme-v1` and `tmu-guide-sound-v1` are listed in `STORAGE_KEYS` but nothing here writes them (no tabs, light only, no sound).

Ids used throughout:

- **CEN100 deadlines** are schedule rows (`integrity`, `matlab-1`, …); completion keys are the 22 dated rows plus `item:y7` (tutorial attendance) and `item:y9` (final exam). The reminders `failure-lab` (Section 29 only) and `showcase-signup` are listed but cannot be marked done; they retire when their item is fully recorded.
- **CEN100 checklist steps** are `${item}-${group}-${check}` (`m2-1-3`): 126 in all, keyed by the order in `content/cen-literals.mjs` (never reorder it).
- **Math** deadlines are assessment ids (`quiz-1` … `final`); preparation steps `${assessment}-${i}`; topic skill steps `${topic}-${i}`.
- **Anchors** (old deep links, keep them as element ids): `assignment-<item>` (CEN), `assessment-<id>` and `topic-<id>` (math). `href` fields are `/<course>/#<anchor>`, without the basePath (Next `Link` adds it).

## API (`@src/lib`)

### Courses

**`COURSES`**, **`COURSE_IDS`**, **`getCourse(id)`**

```js
import { COURSES, getCourse } from '@src/lib';
COURSES.map((c) => c.id); // ['cen100', 'mth140', 'mth141']
getCourse('mth141');
// { id: 'mth141', code: 'MTH141', name: 'Linear Algebra', title: 'Linear Algebra', index: '03',
//   summary: 'Assessment dates, section labs, announced coverage and practice.', description: '…',
//   term: 'Fall 2026', organization: '4 hours of lectures + 1 hour of lab each week', href: '/mth141/',
//   ariaLabel: 'Open MTH141 guide, Linear Algebra',
//   palette: { primary: '#18181B', accentColor: '#FFFFFF', secondary: '#F4F4F5', fillColor: '#FFFFFF',
//              menuColor: '#18181B', menuFontColor: '#FAFAFA', fluidColor: '#E4E4E7', accent: '#004C9B' },
//   links: [{ label: 'Open D2L', href: 'https://courses.torontomu.ca/', external: true }, …textbooks] }
getCourse('nope'); // null
```

**`PALETTES`**, **`DEFAULT_PALETTE`**: every course shares one palette, built from **`TOKENS`** in `palette.mjs` (neutral zinc with one TMU Blue accent; `styles/colors.scss` mirrors it as CSS variables and `tests/palette.test.mjs` keeps the two equal). The same values colour page CSS, course cards and generated 3D textures. Apply them with the original `updateCSSVariables` mapping (`--black` = `primary`, `--white` = `secondary`, `--accent` = `accent`, …) and `setFluidColor(palette.fluidColor)`. The fluid dye is `#E4E4E7` on every route over a black difference-blend base, so the page colour shows unchanged.

**`BADGE`**, **`DISC`**: the printed colours of the lanyard ID badge and the prefooter discs, identical for every course. **`countdownStatus({ ms, done })`** → `'onTrack' | 'soon' | 'urgent' | 'done' | null` (more than 72 h, 72 h or less, 24 h or less, completed); **`STATUS[key]`** gives its colour and badge label. Only the Desk countdown uses these colours.

### Sections and groups

**`sections(courseId)`** → `[{ value, label, detail }]` in the old select's order.

```js
sections('cen100')[28]; // { value: 29, label: 'Section 29', detail: 'Lab: KHS134' }
sections('mth141')[0];  // { value: 1, label: 'Section 1 (011 / 012)', detail: 'Thursday 9:00 AM–10:00 AM · VIC305' }
```

**`getSection(courseId, storage?)`** → number or `null`. **`setSection(courseId, value, storage?)`** → `true` when storage accepted the write (`null`, `0` or `''` clears).

```js
setSection('cen100', 29);  // writes {"section":29,"group":null} (a new section resets the group, as the old select did)
setSection('mth140', 31);  // writes 31
getSection('mth140');      // 31
```

**`groups(section)`** → CEN100 groups of a section (`[{ value: 9, label: 'Group 9' }, …]`). **`getGroup('cen100', storage?)`**, **`setGroup('cen100', value, storage?)`** (needs a saved section; an invalid group saves `null`). **`getProfile(storage?)`** → `{ section, group }` or `null`.

`storage` everywhere: omit it for the browser's `localStorage`, pass `null` for none, or pass any Storage-like object (tests).

### Deadlines

**`deadlines(courseId, { now, section?, storage? })`** → every deadline of a course, sorted by due time (date-only items at 23:59 Toronto of their day, quiz weeks at their Monday, undated last). `section` overrides the saved one (for a live picker).

```js
const items = deadlines('cen100', { now });
items[0];
// { id: 'integrity', courseId: 'cen100', title: 'Academic Integrity Quiz', fullTitle: 'Academic Integrity Quiz due',
//   kind: 'quiz', weight: 2, weightLabel: '2%', due: Date(2026-10-14T19:00Z), precision: 'exact',
//   date: '2026-10-14', week: null, termWeek: 6, dateLabel: 'Wed Oct 14', timeLabel: '3:00 PM Toronto',
//   when: 'Wed Oct 14 · 3:00 PM Toronto', label: 'Due', cta: null,
//   requirement: 'Mandatory D2L quiz. Up to 10 attempts; due at 3:00 PM.', detail: 'Mandatory quiz, 10 attempts.',
//   who: 'Individual', item: 'y4', itemName: 'Academic Integrity Quiz', anchor: 'assignment-y4',
//   href: '/cen100/#assignment-y4', markable: true, done: false, passed: false, overdue: false,
//   target: {…the old resolver's target…}, sortKey: 1792004400000 }
```

- `due` is a `Date` **only** for `precision: 'exact'`; `'day'` (in-class events, "Time not posted"), `'week'` (quiz week without a section, or the Thanksgiving case), `'pending'` (final exams) have `due: null`. Never show a timer for them; use `countdown(item)`, which gives their honest wording.
- `kind`: CEN `quiz | lab | midterm | final | minor | reminder`; math `quiz | midterm | final`.
- `weight`: a number for a row with its own grade (CEN from the old "All 20 graded items" table; math midterm/final). Rows that share a grade (both MATLAB assignments, notebook checkpoints, reflections, presentations; math quizzes) have `weight: null` and say so in `weightLabel` ("MATLAB Assignments (normally pairs) · 10%", "15% quiz category").
- `requirement`: CEN card preview / math scope. `detail`: CEN row note or card text; math date note (timetable, make-up).
- `label` / `cta`: the old resolver's status line ("Due by end of day", "Time not posted · check D2L", "Your lab starts · quiz in its second hour", "Quiz week" + "Choose section for quiz date").
- `done`: a completion record exists. `overdue`: passed and not done. `markable`: can be marked done.

**`deadlineItem(courseId, id, { now, section?, storage? })`** → one item by id, or `null`.

**`buckets(items, now)`** → `{ thisWeek, nextWeek, later, earlier }` by Toronto week (Monday–Sunday). Undated items go to `later`; items dated before this week to `earlier`. Done items are kept; filter them if needed.

```js
const { thisWeek, nextWeek, later } = buckets(deadlines('mth140', { now }).filter((d) => !d.done), now);
```

**`nextDeadline({ now, courseId?, storage? })`** → the next item (same shape) for one course, or across all three when `courseId` is omitted (the old overall rule: exact items by start, an ended item keeps its place for 2 hours after it ends, date-only items at the end of their day, quiz weeks at their Monday, pending last, ties in course order). `null` when nothing is left.

```js
nextDeadline({ now });                     // the Desk's "Next across your courses"
nextDeadline({ now, courseId: 'mth141' }); // a course page's next card
```

**`countdown(itemOrDate, now)`** → `{ label, ms, state, status, days?, hours?, minutes?, seconds?, progress?, sentence? }` with the old wording.

```js
countdown(item, now).label;            // '2d 3h', '5h 07m', '42m', 'Happening now', 'Due time passed'
countdown(dayItem, now).label;         // 'Today', 'Tomorrow', 'In 3 days', 'Date passed (time not posted)'
countdown(quizWeekItem, now).label;    // 'Quiz week' ('Holiday schedule unconfirmed' for the Thanksgiving case)
countdown(finalItem, now).label;       // 'Date pending'
countdown(item.due, now);              // a bare Date or epoch ms counts down as an exact time
countdown(item, now).sentence;         // '1 days and 3 hours remaining until Academic Integrity Quiz. Wed Oct 14 · 3:00 PM Toronto.'
```

`days/hours/minutes/seconds` are present only while an exact countdown runs (truncated, never rounded); `status` is `null` then, otherwise the status line. `state`: `hot` (< 6 h), `soon` (< 48 h), `ahead`, `live`, `passed`, or the precision. Pass the item rather than `item.due` whenever you have it: only the item knows an event's end and its non-exact wording.

**`weeklyChecklist(courseId, { now, section?, storage? })`** → the items due this Toronto week, each with its checklist. CEN rows that share an item's checklist in the same week are one entry with several `records` (Mark done each record id). If this week has nothing, the next week with unfinished work is used and `upcoming` is `true`.

```js
const list = weeklyChecklist('mth141', { now });
list.week;     // { number: 6, label: 'Week 6 · Oct 12–18', start: '2026-10-12', end: '2026-10-18' }
list.upcoming; // false
list[0];
// { itemId: 'midterm', courseId: 'mth141', item: 'midterm', title: 'Midterm Test', due: Date, dateLabel: 'Fri Oct 16',
//   timeLabel: '6:30 PM–8:30 PM Toronto time', done: false, overdue: false, anchor: 'assessment-midterm', href: '…',
//   deadline: {…deadline item…}, records: [{ id: 'midterm', title, done, dateLabel, timeLabel, due }],
//   steps: [{ id: 'midterm-0', text: 'Review all four announced chapters and their exact section ranges.', group: '', checked: false }, …] }
```

`itemId` goes to `markDone`; `step.id` goes to `toggleTick`. CEN steps carry their checklist `group` heading ("Problem statement", or `''`).

**`assessments(courseId, { section? })`** → graded assessments with weights and dates, plus `totalWeight` and `count`. Static (no storage).

```js
const rows = assessments('cen100'); // the old "All 20 graded items" table, in order
rows.count;       // 20
rows.totalWeight; // 100
rows[10];         // { title: 'MATLAB Assignments (normally pairs)', dateLabel: 'Wed Oct 7 · Wed Nov 4', weight: 10, weightLabel: '10%', ids: ['matlab-1', 'matlab-2'], item: 'y2', anchor: 'assignment-y2' }
rows.table;       // the old grouping table (41% / 38% / 42% / 52% / 48%); rows.notes, rows.summary
const math = assessments('mth140');
math[0];          // { title: 'Lab Quiz 1', dateLabel: 'Week of Sep 28', weight: null, weightLabel: '15% quiz category', … }
math.categories;  // [{ title: 'Lab quizzes', weight: 15 }, { title: 'Midterm test', weight: 40 }, { title: 'Final exam', weight: 45 }]
math.totalWeight; // 100
```

**`deskSnapshot({ now, storage? })`** → one entry per course, from the old `deskSummary()`.

```js
deskSnapshot({ now })[0];
// { course: {…COURSES[0]…}, next: {…deadline item…} | null, target: {…old resolver target with status/compact…},
//   progress: { completed: 0, total: 22, ratio: 0, thisWeek: 0 }, urgency: 'ahead', kinds: { final, midterm, quizLab, minor },
//   week: { termWeek: 6, spreadIndex: 5 }, section: 'Section 29' | null, isOverall: false }
```

`progress` counts completion records (never ticks); `thisWeek` counts completed records scheduled this Toronto week.

**`workList(courseId, { now, range: 'week' | 'all', storage?, section? })`** → "What should I work on?" in the old wording: `{ items: [{ itemId, title, dates, progress, target, anchor, href }], status, empty }`.

### Assignment list and calendar events

**`assignmentList(courseId, { now, items? })`** → `{ pastDue, thisWeek, nextWeek, later, done, entries, today, focus }`. Omitted `items` uses `deadlines(courseId, { now })`; pass already-resolved rows to use an explicit section or storage. `now` accepts a `Date` or epoch milliseconds.

```js
const items = deadlines('cen100', { now, section: 29, storage });
const list = assignmentList('cen100', { now, items });
list.entries.length; // 17 (MTH140: 6, MTH141: 7), in content order
list.entries[0];
// { id, courseId, anchor, title, list: 'team' | 'you' | null,
//   rows: [all deadline rows, including reminders], records: [markable rows], recorded,
//   lead, done, pastDue, group: 'pastDue' | 'thisWeek' | 'nextWeek' | 'later' | 'done' }
```

Every content item remains present, including undated items and items with no supplied rows. Anchors match `courseInfo()`. The lead is the earliest unfinished record in deadline order, or the last record when all are done (`null` when there are no records). An item is done only when it has records and all are done; reminders never block completion. Any overdue record puts an unfinished item in `pastDue` before Toronto Monday–Sunday week grouping. Group entries sort by their lead's `sortKey`, with content order breaking ties.

`today` is Toronto `YYYY-MM-DD`. `focus` holds the earliest past-due lead date, today for `thisWeek`, next Monday for `nextWeek`, the first dated lead in `later`, and `null` for `done`. A group with no dated lead has `null` focus.

**`calendarEvents(courseId, items)`** → `[{ id: '<courseId>:<rowId>', rowId, anchor, title, qualifier, style, allDay, start, end }]`. Pass the same deadline rows used for the list. Several rows may link to one assignment anchor. This function only maps the supplied rows; section filtering stays in `deadlines()`.

- Timed events use epoch milliseconds from the resolved target. Only `endOfDay` subtracts a minute, placing the point at 23:59 on the due day.
- Math lab quizzes with an end use the full lab window (`style: 'window'`). A `quizSecondHour` assessment adds " · in your lab's second hour" to the title and explains this in the qualifier; no quiz start time is calculated. Other exact rows use `style: 'due'`, with equal start/end for a point event.
- Day events use the date for both start/end, `allDay: true`, `style: 'day'`, and "Time not posted". Week events use Monday through Friday (`target.week` to `target.weekEnd`, inclusive), `style: 'week'`, "Quiz week · <title>", and "Date depends on your lab section" ("Date needs confirmation" for holiday weeks).
- Pending/empty rows produce no event. Reminders use `style: 'reminder'`; done rows override other styles with `style: 'done'`. Ordinary exact events have an empty qualifier; lab windows say "Lab window" or "Quiz is in your lab's second hour".

Both functions are wrapped in `fast()`, leave their inputs unchanged, and never write storage. They add no React or DOM behaviour.

Contains functions, so use it in components, not in props.

### Progress (completion records, ticks, notes)

**`createProgress(storage?, { events? })`** → the progress API for one storage (default: the browser's). `events` is the `EventTarget` that receives cross-tab `storage` events (default `window`). In components use `useProgress()`, which shares one instance so Mark done and Undo work across components (**`sharedProgress()`** returns it outside React).

```js
const progress = createProgress();
progress.isDone('cen100', 'integrity');            // false
const result = progress.markDone('cen100', 'integrity');
// { changed: true, saved: true, message: 'Marked done: Academic Integrity Quiz due, 3:00 PM Toronto time. Saved on this device.' }
// saved: false → message ends 'Local saving is blocked; export a backup to keep it.' (the change still shows on this page)
progress.canUndo();                                // true
progress.undo();                                   // { courseId: 'cen100', itemId: 'integrity', saved: true } (or null)
progress.setDone('cen100', 'item:y9', true);       // a completion checkbox; clears a pending Undo

progress.isTicked('cen100', 'm2', 'm2-1-3');       // CEN requirement checklist
progress.toggleTick('cen100', 'm2', 'm2-1-3');     // { checked: true, saved: true }; pass a 4th argument to set instead of toggle
progress.toggleTick('mth141', 'midterm', 'midterm-0');     // math preparation check
progress.toggleTick('mth140', 'functions', 'functions-0'); // math topic skill check
progress.tickCount('cen100', 'm2');                // { checked: 1, total: 19 }
progress.clearTicks();                             // CEN "Clear my ticks" (ask first: courseCopy('cen100').clearTicksConfirm)

progress.setNote('cen100', 'm2', 'Interview list'); progress.getNote('cen100', 'm2');
progress.setTarget('mth141', 'final', '2026-12-01'); progress.getTarget('mth141', 'final');

const off = progress.subscribe(({ key, courseId, source }) => rerender()); // source: 'local' | 'storage' (another tab)
off();
```

Ticks never mark anything done and Mark done never ticks. A step id may be the full key or its index part under the item (`toggleTick('cen100', 'outline', '1-3')` → `m2-1-3`). CEN notes and targets are per card (`m2`); math per assessment. As on the old pages, a completion change made in another tab cancels a pending Undo for that course.

### Search

**`searchIndex({ now, storage?, course?, motionForced? })`** → every searchable entry, in the old palette's groups: Courses (places; the page's course views), Assessments (every deadline of every course, hinted `CODE · when · label · cta · note`), Weeks (the semester spreads, each opening its first deadline), Topics (math), Actions (This week's work / Contacts / Export calendar on a course page, Pause/Play motion, Open D2L). `course` is the current page's course: its items lead and its next deadline is a default entry (without `course`, the overall next deadline is). The array carries `.weeks` for week queries.

```js
const entries = searchIndex({ now, course: 'cen100' });
entries[0]; // { group: 'Courses', groupLabel: 'Courses', title: 'Desk', detail: 'TMU Course Guides', href: '/', keywords: '', id: 'place-desk', type: 'place', default: true }
// other fields as relevant: courseId, precision, done, disabled, ariaLabel, index (weeks), action, external
```

**`searchEntries(entries, query)`** → ranked results with the old palette's rules: empty query → the default entries; otherwise fuzzy subsequence scoring, keyword matches lower, groups ordered by their best hit; "week 9", "wk 9", "w9", "oct 13" and ISO dates put that week first. Each result adds `match: { score, indices }` (indices into `title`, for highlighting).

```js
searchEntries(entries, 'integrity')[0].href; // '/cen100/#assignment-y4'
searchEntries(entries, 'week 9')[0].title;   // 'Week 9 · Nov 2–8'
```

**`searchGuide(query, { course?, limit = 12 })`** → the old pages' full-text "Search the guide" (every word must appear; accents ignored) over CEN cards, rules and contacts and math assessment/topic cards: `{ results: [{ courseId, title, tab, href }], status: '2 results.' | 'No matches. Try a shorter term.', total }`.

**`SEARCH_COPY`**, **`SEARCH_GROUPS`**: the old palette's interface copy (`title`, `placeholder`, `label`, `suggestion(q)`, `empty(q)`, `results(n)`, …) and group headings → screen-reader labels.

### Guide tools

```js
calendarFile('cen100', { now, item: 'all', upcomingOnly: true, reminderDays: 1 });
// { ok: true, name: 'cen100-deadlines-2026.ics', type: 'text/calendar;charset=utf-8', text, count, message: 'Calendar file ready with 13 entries. …' }
calendarFile('mth140', { now, includeTentative: true, upcomingOnly: true }); // { ok: false, message: 'Choose your section first to include lab quiz dates.' } without a section
exportBackup('cen100', { now });      // { name: 'cen100-progress-2026-10-15.json', type: 'application/json', text, message }
importBackup('mth141', fileText);     // { ok, saved, message: 'Progress imported.' | the old error message }
hasUnseenUpdates('mth140');           // true while the course has a course update newer than the one last opened
markUpdatesSeen('mth140');
getHideCompleted(); setHideCompleted(true); // CEN "Hide fully checked items"
```

The page does the download (`new Blob([file.text], { type: file.type })` + `<a download={file.name}>`) and the file picker (`await file.text()`, at most 250 KB for CEN and 300 KB for math). Calendar UIDs and backup formats are the old ones, so re-imports update instead of duplicating.

### Motion

**`motionPaused(storage?)`** → the saved "Pause motion" choice. **`setMotionPaused(value, storage?)`** → `true` when saved. The device's reduced-motion setting is separate; `useMotionPaused()` combines both.

### Other exports

- **`STORAGE_KEYS`**: the key table above (`STORAGE_KEYS.cen100.plan`, `STORAGE_KEYS.motion`, …).
- **`subscribeKeys(storage, callback, target?)`**: the change listener behind `progress.subscribe` (needs the resolved storage object).
- **`DESK_TEXT`**, **`PRIVACY_TEXT`**: the old Desk and privacy pages' text (`DESK_TEXT.lede`, `.nextHeading`, `.nextStatic`, `.courses`, `.footer`; `PRIVACY_TEXT.paragraphs`, `.updated`). The course pages' text is in `courseInfo(id).page`.

## Hooks (`@src/lib/react`)

```js
import { useNow, useProgress, useSection, useMotionPaused } from '@src/lib/react';

const now = useNow(60000);        // Date, refreshed on each wall-clock minute (1000 for seconds) and on tab return; null until mounted
const progress = useProgress();   // the shared progress API; re-renders on any change here or in another tab; { …api, version, ready }
const [section, setSection] = useSection('mth140'); // saved section or null (null until mounted); setSection(31) → saved?
const [still, setPaused, motion] = useMotionPaused();
// still: device reduced motion, ?motion=off, or the saved pause; setPaused(true) saves "true"; motion = { saved, reduced, forced, full }
```

Typical course-page wiring:

```js
const now = useNow(60000);
const progress = useProgress();
// Saved state changes (Mark done, ticks, setSection here or in another tab) bump progress.version.
const items = useMemo(() => (now ? deadlines(courseId, { now }) : []), [now, progress.version, courseId]);
const next = items.find((item) => !item.done && !item.passed && item.markable);
// <button onClick={() => setMessage(progress.markDone(courseId, next.id).message)}>Mark done</button>
// {progress.canUndo() && <button onClick={() => progress.undo()}>Undo</button>}
```

`useMotionPaused` reads synchronously on the client's first render (so a loader can be skipped from the start); every other hook starts empty and fills in after mount.

## Performance

The vendored date code builds a new `Intl.DateTimeFormat` (or calls `toLocaleDateString`) for every date it touches, about 50–100 µs each; a Desk snapshot touches dates thousands of times. Because the vendored files must stay identical to the old site's, `perf.mjs` swaps in caching versions of those two globals for the duration of each synchronous public call and restores them in `finally`. Typical costs on a laptop: `deadlines` 2 ms, `nextDeadline` 0.3 ms, `weeklyChecklist` 1.5 ms, `deskSnapshot` 9 ms, `searchIndex` 12 ms (build the index once when the search panel opens). The parity tests compare every output with the old modules running without the cache.

## Tests

`npm test` (`node --test tests/`) runs `site/tests/*.test.mjs` in one process (Node resolves the folder through `tests/package.json` `main`); `node --test tests/*.test.mjs` runs them one process per file. They import the old modules from the repo's `assets/` folder by file URL and evaluate the old page closures from their source, then check:

- `vendor.test.mjs`: the vendored files are the old ones with only `?v=` removed; no DOM or globals at import.
- `content.test.mjs`: extracted content and helpers equal the old closures' (literals, cleanPlan/validProfile/cleanProgress, completion text, section texts, calendar, backup parsing, work list, math checklists, rules and notices).
- `deadlines.test.mjs`: the Toronto cases of the old `tests/targets.test.mjs`; next deadline per course and overall, every item's target and countdown wording over ~230 clocks × saved states; buckets; weekly checklist; the Desk snapshot against the old `deskSummary()`.
- `assignments.test.mjs`: content partitions and anchors, completion and reminder grouping, Toronto week edges and focus dates, calendar precision, lab windows, end-of-day/DST boundaries, section filtering, and unchanged inputs.
- `boundaries.test.mjs`: the 40 Toronto boundary fixtures (`docs/qa/toronto-deadline-test-cases.json`) through `countdown()`, also with the computer in UTC, Los Angeles and Tokyo.
- `storage.test.mjs`: round trips for every key, including values written by the old site, byte-equal to the old pages' writes; readers never write; backups and calendar files.
- `progress.test.mjs`: Mark done / Undo, ticks separate from completion, cross-tab events and Undo cancellation.
- `blocked.test.mjs`: empty, missing, blocked (throwing getter or methods) and full storage.
- `api.test.mjs`, `react.test.mjs`: shapes, wording, search ranking, hooks rendering on the server.
